# Quickshell shell (`.config/quickshell/sunebi`)

## Run and debug

- Start with `qs -c sunebi`, logs with `qs log -c sunebi`, running instances with `qs list --all`. Hyprland autostart also launches it.
- After swapping the config directory, an already running `qs` keeps the old code in memory. Stop the old instance before judging a change.
- Hot reload sometimes fails on a just-created file (`X is not a type`, `module ... is not installed`). `touch shell.qml` retries it.
- After many hot reloads the Hyprland socket can drop (`PeerClosedError`) and workspace state freezes. Restart `qs` completely.

## Where things live

- `Config.qml`: behavior settings (volume steps, date formats, workspace count). Not colors or sizes.
- `Theme.qml`: radii, bar and island sizes, fonts. No colors.
- `Colors.qml`: the colors of the chosen theme (shadcn tokens) for the system color scheme from `services/ColorScheme.qml`. The code asks it for colors, never `Theme`. It is not called `Palette`, that is a QtQuick type and shadows it.
- `services/`: singletons. A skeleton inherited from end-4/dots-hyprland with the hearing protection removed. Check usage before deleting anything.
- A service with its own configuration or external program has a folder of its own, and the folder is a QML module (`import qs.services.cava`): `services/cava/` holds `AudioVisualizer` and `cava.conf`, the settings of cava with three values the shell fills in. The simple services, the wallpaper and the themes among them, stay in `services/`. The data directory of the themes, `themes/`, stays at the root because the JSON files are the user's to edit.
- `components/`: the pieces several modules share, which know no service: `Capsule`, `StyledText`, `StatusLabel`, `CoverArt`, and in `components/menu/` the `ContextMenu` of the tray. A folder is a QML module, so a type of another folder needs `import qs.<folder>` and a type of the same folder needs nothing.
- `modules/bar/`: the bar window, `Bar`, `Workspaces`, `SystemTray`, `TrayItem`.
- `modules/resources/`: the CPU, RAM and GPU pill, `ResourceMonitor` and `ResourceRing`.
- `modules/island/`: the Dynamic Island and what it opens into, `DynamicIsland`, `IslandDismissLayer`, `IslandMedia`, `IslandVolume`, `IslandWallpaper`, `IslandCarousel`, `IslandSessionMenu`, `SessionButton`, `ThemeCard`.
- Dynamic Island: always a pill that widens with its content (`Theme.islandIdleWidth`, `islandMediaWidth`, `islandVolumeWidth`), empty while idle. It shows the cover and six `cava` levels of the playing player, or the volume bar for a moment after it changes. `services/Media.qml` picks the player: only the apps in `Config.mediaPlayers` (matched by desktop entry) count, so other browsers and the Chromium process Spotify starts for its ads are ignored, then `Config.mediaPlayerPriority`, then the one that started last. `services/cava/AudioVisualizer.qml` runs `cava` (it must be installed) on that app's PipeWire stream, so other apps do not move the bars. A browser has one stream for every tab that played a sound, all named after the browser, so the stream is chosen by the page title or the artist of the player (`media.name`; Twitch reports the title of the broadcast, only its channel is in the tab name), then by having a driver (`node.driver-id`, only the streams that carry sound have one), then the newest `object.serial`, which is what `cava` gets as its source. The date and time live in the tray.
- Resource pill: `ResourceMonitor` sits right of the workspaces with one `ResourceRing` each for CPU, RAM and GPU, filled clockwise with the load and red from `Config.resourceHighLoad`. `services/ResourceUsage.qml` samples `/proc/stat`, `/proc/meminfo` and the amdgpu `gpu_busy_percent` at `Config.gpuBusyPath` (the card number differs between machines) every `Config.resourceRefreshMs`. The symbols are `cpu`, `memorychip` and `display` (there is no gpu symbol). The codepoints of newer symbols are not in the font's glyph names, `gist.github.com/g-cqd/ce0cb34240faffb4c1b6f18d116f516f` maps names to characters.
- Wallpaper: `services/Wallpaper.qml` lists `Config.wallpaperDir` (`~/Pictures/Wallpapers`, name order) and sets the image with `awww img` (the `awww-daemon` from Hyprland autostart restores the last one after a restart). `SUPER+CTRL+W` opens the island on the focused screen into `IslandCarousel` (a carousel of three cards, the bar window takes the keyboard while it is open): left and right, A and D or the wheel move, Enter, Space or a click on a card apply, Escape or a click outside closes. The strip stops at its ends, so the first and the last card sit at the edge of the island. The shuffle button in the footer (the SF Symbol `shuffle`) applies a random one through `Wallpaper.random()` and closes the menu. Every apply makes the island show `IslandWallpaper` (preview and name) for `Config.wallpaperHudMs`. `CoverArt` keeps the previous picture until the next has loaded, a big PNG can take a moment.
- Session menu: `services/SessionMenu.qml` holds the actions (Sleep, Log Out, Lock, Reboot, Shut Down) and runs them. `CTRL+ALT+DELETE` opens the island on the focused screen into `IslandSessionMenu`: the uptime on top, five `SessionButton`s and the name of the one in focus. Left and right, A and D or the pointer move the focus, Enter, Space or a click run it, Escape or a click outside closes. Reboot and Shut Down only run after the button was held for `Config.sessionHoldMs`, a ring around it shows how far the hold is. The icons are SF Symbols private use characters of SF Pro Text (the font has no symbol names, the codepoints are in `SessionMenu.qml`). Lock runs `hyprlock` if it is installed, otherwise `loginctl lock-session`, which does nothing without a locker.
- Color themes: one JSON file per theme in `themes/` (the file name is the id, `default` is the first one), `name` plus a `light` and a `dark` object with the 18 shadcn tokens. A theme with one scheme only keeps it in the other. Colors are QML `#AARRGGBB`, so a color with alpha has the alpha first. `SUPER+CTRL+T` opens the same `IslandCarousel` with a card per theme (`ThemeCard`: the background, an `Aa` in the text color and four swatches), `services/Themes.qml` scans the directory when it opens and keeps the choice in the state directory (`theme.json`). `Colors` re-reads the file of the chosen theme when it changes, so a theme can be tuned with the shell running. `SUPER+CTRL+SHIFT+D` flips light and dark, which every theme follows.
- Closing by a click outside: the bar window only takes input on its capsules, so while the wallpaper carousel or the session menu is open `IslandDismissLayer` covers every screen with a transparent window (with a hole for the island) and closes the menu on any click in it, whatever window is below. It exists only while a menu is open, so nothing stays blocked afterwards. The bar takes the keyboard (`Exclusive`) for the same time.
- Tray context menu: a right click on a tray icon (a left click too on an icon that is a menu only) opens `ContextMenu` from `components/menu/`, in the look of shadcn/ui, instead of the native menu of the app. It has no border and no shadow, it is a `PopupWindow` with `grabFocus`, so a click elsewhere closes it, and it lists the entries of a `QsMenuOpener` on the menu of the item: rows with a hover highlight, separators, a dimmed disabled entry, a check or a dot for a checked entry, a chevron for a submenu. The anchor is a rect fixed when the menu opens (`TrayItem.toggleMenu()`). The menu takes the focus from the bar, which makes the `HyprlandFocusGrab` of `SystemTray` dismiss the overflow popup the icon is in, and listing the menu window in the grab does not help, the clear comes in the same moment as the focus change. So `SystemTray` ignores that clear while a menu is open (`menuOpen`) and closes the popup when the menu closes. A submenu is another `ContextMenu` made with `Qt.createComponent` (a type cannot instantiate itself in its own file) and anchored by a rect of its window: with `anchor.item` set the rect is ignored and the submenu lands on its row. It goes the side its menu goes and turns around only when the screen has no room, worked out from `screenX` and `screenWidth`, because a flip by the compositor lands on the menu the submenu comes from. There are no icons and no keyboard navigation yet.
- Tray overflow: items not pinned live in a popup drawn inside the bar window (a `PopupWindow` cannot receive a dragged icon), so `Bar` is taller than its `exclusiveZone`. Drag a bar icon onto the chevron to hide it (the chevron also appears during a drag when nothing is hidden yet), drag a popup icon into the bar to pin it, or drop an icon onto another icon of the same place to swap them. Apps seen for the first time start hidden. The choice and order are saved by `services/TrayPins.qml` in `~/.local/state/quickshell/by-shell/<id>/tray.json`, keyed by the item `id` from `SystemTrayItem`.

## Conventions

- Imports: external block first (`Quickshell`, then `Quickshell.*`, then `QtQuick`), a blank line, then internal (`qs`, then `qs.*`).
- All bar text goes through `StyledText`: native rendering follows fontconfig, Qt's own rasterizer adds color fringes.
- Fonts are SF Pro Text and SF Pro Display, icons come from SF Pro Text. Capsules have no outline.
- Names follow https://tum-esi.github.io/common-coding-conventions: no abbreviations, no generic names.

## Checks

- Format: `/usr/lib/qt6/bin/qmlformat <file>` must print the file unchanged. VSCode formats qml on save.
- `qmllint` noise that code cannot fix: `Type X not declared as singleton in qmldir` (a real `qmldir` does not help), `PanelWindow is not creatable`, `Member "values" not found on UntypedObjectModel`.
- Screenshots: `grim -g "x,y WxH"` uses global coordinates. DP-2 starts at 0,0 and DP-1 at 1920,0.
- No input emulation tool is installed. `hyprctl dispatch 'hl.dsp.cursor.move({ x = .., y = .. })'` moves the cursor but delivers hover events unreliably, so click and wheel need a manual check.
